# 测试与验证规范

## 验证层级

- Agent 先运行触及范围最小的检查，再运行项目要求的完整检查。
- 修改纯函数或状态逻辑时补充单元测试。
- 修改组件交互时测试用户可观察行为，不断言内部 state 或实现细节。
- 修改路由、认证、支付、数据提交等关键流程时补充集成或端到端验证。
- 修复缺陷时添加能在修复前失败、修复后通过的回归测试；项目没有测试设施时记录可复现的人工步骤。

## 完成条件

- 运行项目配置的 lint、类型检查和测试命令。未配置的命令标记为“未配置”，不得用构建命令代替。
- Agent 不删除失败测试、不放宽断言，也不扩大忽略范围来获得通过结果。
- 区分本次改动引入的失败与仓库原有失败，并提供命令和错误摘要。

## 边界案例

至少检查加载、空数据、失败、重复操作、快速切换、权限不足和窄屏场景中与本次改动相关的项目。
