# 工程基线

## 范围

- Agent 先确认任务边界、现有实现和仓库状态，再修改文件。
- Agent 只改动完成任务所需的文件。发现相邻问题时记录问题，不顺带重构。
- Agent 保留用户的未提交改动。无法安全绕开冲突时，停止写入并说明冲突文件。

## 实现原则

- 优先沿用仓库已有组件、工具函数、目录和命名方式。
- 用最小完整改动满足验收条件，不引入未被需求使用的抽象层。
- 删除被新实现取代的死代码、无效导入和临时调试输出。
- 缺少业务数据时保留空值或使用项目约定的空状态。Agent 不推算、拼接或虚构字段值。
- 修改公共接口、路由、存储格式或组件契约时，记录兼容性影响和迁移方式。

## 文件边界

- Agent 不修改生成目录、构建产物和依赖目录。
- Agent 不手工编辑锁文件。依赖管理命令负责更新锁文件。
- Agent 不创建与现有文件职责重复的 `utils`、`common` 或共享组件。

## 非业务产物

- 除任务明确要求的业务源码、项目配置和正式交付物外，Agent 不在仓库内创建计划、报告、截图、日志、临时脚本、导出数据、浏览器产物或测试夹具。
- 非业务产物默认写入 `90-project-overrides.md` 配置的项目外工作目录，并按任务集中到一个子目录。
- 工具或框架确实要求产物位于仓库时，Agent 将其集中到项目配置的单一目录。若固定发现机制要求分散到多个路径，写入前必须取得用户确认；项目已明确批准的固定入口除外。
- 新增需要长期提交到仓库的测试文件前必须取得用户确认；临时回归脚本和诊断夹具始终放在项目外。
